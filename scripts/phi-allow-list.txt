# scripts/phi-allow-list.txt
#
# PHI-scan allow-list, the positive declaration that a fixture's identifiers
# are synthetic. `scripts/phi-scan.ts` reads this file; any realistic-PHI-shaped
# token NOT covered here is a hit.
#
# mllp is a TRANSPORT/framing library: it wraps HL7 v2 messages in MLLP frames
# (`VT + payload + FS CR`). Its data fixtures are therefore MLLP-framed HL7 v2
# messages (`test/**/*.frame.bin`), whose PHI shapes are IDENTICAL to `@cosyte/hl7`'s.
# The scanner strips the MLLP frame, then runs the same HL7 v2 segment/field-aware
# detection hl7 uses. A framed binary fixture is byte-strict at the front (the VT
# start-block, then the MSH segment), so it cannot carry an inline `# synthetic:
# true` header, that would break every framing test. This allow-list is therefore
# the synthetic-fixture declaration mechanism, the same approach `@cosyte/hl7`,
# `@cosyte/dicom` (binary `.dcm`) and `@cosyte/x12` (byte-strict `.edi`) use.
#
# Format: `<TAG> <value>` per line. `#` comments and blank lines are ignored.
#   NAME <token>          synthetic person-name word (XPN / XCN name components +
#                         site-defined Z-segment names), matched case-insensitively
#   DOB <YYYYMMDD|YYYY>   synthetic date of birth (PID-7 / NK1-16), normalized
#   ADDR <street line>    synthetic street address (XAD component 1, e.g. PID-11),
#                         matched case-insensitively
#   ID <value>            synthetic id that legitimately matches an SSN / bare-MRN
#                         (6-9 digit) shape (PID-19, CX SS-typed, PID-3/-18)
#   EMAILDOMAIN <domain>  reserved / test email domain that is allowed to appear
#
# To add a new synthetic fixture: reuse the tokens below, or append new ones here
# and commit. Adding a token is a reviewed, intentional act, never silent.

# --- Tokens the INDEX corpus reached first ----------------------------------
# `all` mode now also reads the bytes git carries at every path in the index, not
# only the files under `test/` and `src/`. That opened 32 tracked non-markdown
# files that NEITHER route had ever read, and two of them carried a token this
# scanner reports. Both were already committed; neither is new content and
# neither is PHI.
#
# `package.json` : the published `author` field, `Cosyte <hello@cosyte.com>`.
# COST, STATED BECAUSE IT IS GLOBAL AND ROUTE-BLIND: this allow-list has no
# exact-address tag, only EMAILDOMAIN, so declaring this one address switches the
# email detector off for EVERY address at this domain, in every file, on every
# route. That is accepted deliberately: `cosyte.com` is the company's own domain
# and a patient's contact address is never at it, so the detection actually given
# up is a corporate address the gate should not be reporting anyway. It is NOT a
# licence to add a domain a patient could plausibly be reached at. Narrowing this
# would mean adding an exact-address tag to the format, which every sibling's
# allow-list parser would then diverge on: its own slice, not this one.
EMAILDOMAIN cosyte.com
#
# `scripts/phi-scan.ts` : `<family>` and `<given>`, the METAVARIABLE PLACEHOLDERS
# in this scanner's own docblock for `extractEmbeddedHl7`, which documents the
# shape `"PID|1||<mrn>^^^HOSP^MR||<family>^<given>||<dob>|F"`. The recogniser
# recovers that run and reads the two placeholders as PID-5 name components,
# which is the detector working correctly on text that only looks like a message.
# COST: these two words are now allowed as name tokens corpus-wide, so a patient
# whose actual name is "Family" or "Given" is not reported. Accepted as
# negligible against the alternatives, both of which are worse: exempting
# `scripts/phi-scan.ts` wholesale via DELIBERATE_VIOLATOR_SOURCES would drop the
# SSN / email floor on the scanner's own source (the gate excusing itself), and
# teaching the detector to ignore `<...>`-wrapped tokens would weaken it for
# every real fixture, since `<` is not special in HL7 v2.
NAME FAMILY
NAME GIVEN
