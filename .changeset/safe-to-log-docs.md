**The docs now say, field by field, what is safe to log from a live link, and no example prints a whole message, an acknowledgment or a control id read off the wire.** A new "What is safe to log" section on the options page names, for every event, hook, error and report (the shutdown report included), the fields that can hold message bytes (the `message` and `ack` events' `payload`, the `ack` event's `controlId`, the `onCommitAck` report's `payload`, a framing error's one-byte `snippet`, and an `ack-from-hl7` result's `frame`, `payload`, `ack` and `correlationId`) and the fields that hold only codes, counts, byte lengths, offsets and times. Four API reference samples printed message content and now print a length or a code instead: `client.send()` logged the whole acknowledgment, the `InMemoryTransport` samples printed raw chunks, and the `MllpAck` sample printed the echoed control id. The README and the reliability page no longer say that no event payload carries message content, which the `message` and `ack` events do by design, and the options page now gives the `error` event's payload as it is: `{ connectionId, error }` on a client and for a connection's error on a server. Nothing a caller must change.
