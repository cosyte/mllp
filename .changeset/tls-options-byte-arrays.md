**Every byte array in the `tls` options is copied, and a `tls` that is an array or another kind of object is refused.** The copy taken at creation gave new bytes only to a `Buffer`, so a `cert`, `key`, `ca` or `pfx` passed as a plain `Uint8Array` (outside the declared type, but Node.js accepts it) stayed the caller's: bytes overwritten in it after creation changed what a client presented on reconnect. Now every `ArrayBuffer` view (a `Buffer`, a `Uint8Array`, any other typed array, a `DataView`) is copied the same way, as a `Buffer` of the bytes it covers. A `tls` that is an array, or an object that is not an object of options (a byte array, a `Map`, a `Date`, a boxed primitive), now throws `MllpTlsConfigurationError` with `MLLP_TLS_OPTIONS_NOT_AN_OBJECT` from `createClient`, `createServer` and both constructors; before, a client given an array connected with TLS defaults and a server threw a `TypeError` asking for `cert` and `key`. A literal, a class instance and an `Object.create` object are still accepted; a caller who passed anything else must pass a plain options object. A client now loads its `pfx` once, when it is created, rather than on every connect and reconnect: a file that cannot be loaded still rejects every `connect()` with `MLLP_TLS_PFX_REJECTED` before a socket is opened, and a reconnect no longer spends the time to load the same bytes again.
